# Project Workspace

Use the Workspace below to complete the project with the provided software, starter files, and Census dataset.

The Workspace opens the repository directory:

```bash
/workspace/nd0821-c3-starter-code/
```

Run commands from the directory containing `setup.py` and `main.py`; in older Workspace copies, this is the repository's `starter/` directory. See **Instructions > Project Directory**.

## Working with a Repository

You may complete the implementation entirely in the Workspace or use the Workspace together with a GitHub or Azure Repos repository.

- If you use **GitHub**, commit and push your final work to the GitHub repository that you will submit.
- If you use **Azure DevOps**, commit and push your final work to the private Azure Repos repository. Normal Git commands do not change when the remote is Azure Repos.

Include the final trained model and fitted preprocessing artifacts in every submission, including Workspace and ZIP submissions. Saving a file in the Workspace does not add it to Git: follow **Instructions > Required Model Artifacts** to explicitly stage ignored files before committing and pushing.

Download a backup of your work regularly. Before leaving the Workspace, confirm that all required source files, model artifacts, screenshots, and documentation have been saved and pushed to the repository platform you selected.

Do not store personal access tokens, passwords, API keys, deploy hooks, or other credentials in project files, notebooks, shell-history files, screenshots, Git commits, or pipeline YAML.

The Workspace submission button is not the Azure DevOps submission workflow. If you use Azure Repos, follow the fresh-clone ZIP procedure on the **Project Submission** page so that the reviewer receives the final source and Git history without requiring access to your private Azure DevOps project.
