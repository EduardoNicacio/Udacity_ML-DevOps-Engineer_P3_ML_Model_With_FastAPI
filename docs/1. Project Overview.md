# Project Overview

In this project, you will apply the skills acquired in this course to develop a classification model using publicly available Census Bureau data. You will create unit tests to monitor the model's performance across different data slices. Then, you will deploy your model using the FastAPI framework and implement API tests to verify its functionality.

You will also build a continuous integration and continuous deployment (CI/CD) workflow. You may use either of the following platform workflows:

- **GitHub**: Store the project in GitHub, run continuous integration with GitHub Actions, and deploy the application after the checks pass.
- **Azure DevOps**: Store the project in Azure Repos, run continuous integration with Azure Pipelines, and deploy the application from a deployment stage that runs only after the checks pass.

The implementation and evaluation requirements are the same for both workflows. Use one workflow consistently and follow the **GitHub to Azure DevOps Translation Guide** earlier in this course when you choose Azure DevOps.

## Choose Where to Work

A Workspace with the required software and dataset already installed is provided for you to complete the project. You may instead work in your own local environment.

### Udacity Workspace

Use the Project Workspace later in this lesson. Download a backup of your work regularly. If you plan to use GitHub or Azure DevOps for version control and CI/CD, push your Workspace changes to the repository platform you selected.

### GitHub

Download, fork, or clone the public [project starter repository](https://github.com/udacity/nd0821-c3-starter-code), and store your completed project in your own GitHub repository.

### Azure DevOps

Import the public [project starter repository](https://github.com/udacity/nd0821-c3-starter-code) into an Azure Repos repository in your Azure DevOps project. You can then clone the imported repository and complete the project locally or transfer files between the repository and the Udacity Workspace.

New public Azure DevOps projects cannot normally be created, so your Azure Repos URL might not be accessible to a Udacity reviewer. This is expected. Do not invite an unknown reviewer to your Azure DevOps organization or weaken your project's security settings. The **Project Submission** page explains how to submit a complete-repository ZIP created from a fresh local clone of the final Azure Repos repository.
