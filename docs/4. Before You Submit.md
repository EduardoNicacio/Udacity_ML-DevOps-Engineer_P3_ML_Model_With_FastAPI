# Before You Submit

## Common Mistakes in Project Submissions

Before submitting, confirm that your project does **not** contain any of the following common mistakes.

### I. FastAPI documentation does not include example values

Review **API Creation > Create a REST API** in the [project rubric](https://learn.udacity.com/rubric/5033). Your generated FastAPI documentation must show example values for every request parameter. For example, a parameter named `tax` could have the example value `100.35`.

See the [FastAPI documentation about request examples](https://fastapi.tiangolo.com/tutorial/schema-extra-example/) for implementation guidance.

### II. Tests do not cover every possible model output

- The `GET` test must check both the status code and the contents of the response.
- Include a separate test for **each** possible inference or prediction returned by the model.
- Run `python sanitycheck.py` as described on the Instructions page, resolve the reported problems, and compare the final tests with the rubric.

### III. Repository evidence is missing

Provide the evidence required for the repository platform you selected:

- **GitHub**: Include the GitHub repository URL in `README.md` or the submission comments, even when you use **Select GitHub repo** to submit.
- **Azure DevOps**: Include the Azure Repos URL in `README.md`, but do not expect the reviewer to open the private URL. Submit a complete-repository ZIP created from a fresh local clone of the final Azure Repos repository. The ZIP must include the `.git` directory so that the reviewer can inspect the source and commit history offline.

Do not invite an unknown reviewer to your Azure DevOps organization, make the project public, or weaken its security controls. Before compressing an Azure Repos clone, verify that `.git/config` contains no personal access token, password, or other credential.

### IV. A required screenshot is missing or incorrectly named

Include every screenshot required by the rubric and use the required filenames. Each screenshot must clearly show the requested evidence. In particular, use the corrected filename `continuous_deployment.png` for the continuous-deployment screenshot.

The starter ignores images in `screenshots/`. Follow **Instructions > Required Screenshots** to explicitly commit each required image, then verify that it is present in the final repository or submission ZIP.

### V. Required model artifacts are missing

Include the final trained model and all fitted preprocessing artifacts needed for inference. Files ignored by `.gitignore` still need to be submitted; follow **Instructions > Required Model Artifacts** to commit them explicitly.

## Task List

Before submitting:

- [ ] `pytest` passes.
- [ ] `flake8` passes without errors.
- [ ] `python_sanitycheck.py` passes, or every reported false positive has been checked against the rubric.
- [ ] All required screenshots are included and correctly named.
- [ ] The FastAPI documentation contains request example values.
- [ ] API tests cover the `GET` response and every possible model prediction.
- [ ] The live `GET` endpoint works.
- [ ] The live `POST` request script returns an inference result and HTTP status code.
- [ ] Continuous integration runs `pytest` and `flake8` on the selected platform.
- [ ] Continuous deployment runs only after continuous integration succeeds on the protected branch.
- [ ] `README.md` identifies the repository platform and contains its repository URL.
- [ ] No secret or confidential information is present in the source, Git history, screenshots, or pipeline configuration.
- [ ] **For GitHub**, the submitted repository is accessible to the reviewer.
- [ ] **For Azure DevOps**, the submission is a fresh-clone ZIP containing `.git/HEAD` and `.git/config`; `.git/config` contains no credentials.
- [ ] A fresh clone or extracted submission includes the final model and required fitted preprocessing artifacts and can run inference without retraining.
